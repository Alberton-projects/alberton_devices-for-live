# Alberton Kit Selector

The panel of a distributed instrument: sixteen strips, each a program and a volume, nine fx
banks of nine macros with a volume each, and a Main volume, stored as *kits* and recalled
from a grid or by a MIDI program change. The panel knows nothing about the set. It
broadcasts on a bus, and an **Alberton Kit Receiver** on each track and an **Alberton Kit FX
Receiver** by each rack decide what a strip or a bank means there. The three devices together
are described in [`docs/PROTOCOL.md`](../../docs/PROTOCOL.md).

Put the panel on a MIDI track. For program changes to reach it, that track must be **armed or
monitoring In**.

## What a kit holds

| | |
|---|---|
| Strips 1–16 | `Program` 0–127 and `Volume` 0–1 each; the label under a strip is the name of the track whose receiver is bound to it |
| Fx banks 1–9 | nine macro values 0–127 (the slider) and an `FX Volume`; the bank labels (drums, bass, pads, pianos, leads, loops, vocoder, vocals, resample) are only labels, a receiver binds to the bank's number |
| `Main` | the set's main volume, the one thing the panel writes to Live itself |
| The name | the text field under the grid |

`MIDI Ch` and `Bus` are settings, never part of a kit.

## Using it

- **Store**: set the dials, then shift-click a cell of the grid. **Recall**: click it. Thirty-two
  cells.
- **By MIDI**: program change *n* on `MIDI Ch` recalls kit *n + 1*.
- **Send** sends everything again, in order (programs one every 150 ms, so instruments that
  choke on a burst of program changes get them one by one; `pc_interval <ms>` changes that).
- **Refresh** asks every receiver to introduce itself and relabels the strips.
- **FX Capture** reads the racks' macros through the fx receivers into the sliders, to store
  what is sounding now.
- `Bus` 1–4 lets two panels coexist in one set; receivers listen on the same bus number.

Source: `kit-selector.js`, embedded in the `.amxd`. The patcher is generated by
`tools/build_devices.py`.
